# リピごち ![Tier](https://img.shields.io/badge/tier-hobby-blue)

> 今夜を決めて、必要なものだけ買って、おいしかった一品を残す。

## これは何？

リピごちは、1人・2人暮らしの夜ごはんを1日1品提案する、ごはんメモです。
好み・調理時間・器具・常備品に合わせて数日分を決め、買い物と「作った」の記録までつながります。現在は無料で利用できます。

## こんな時に使えます

- SNSで見つけたレシピ動画をあとから探し直したいとき
- 家族ごとの「また食べたい」ペースを残したいとき
- 忙しい週の献立候補を、保存済みレシピからさっと決めたいとき

## 使い方

- デモ: https://165cm.github.io/matagochi/
- スマホではブラウザの「ホーム画面に追加」でアプリとして使えます（PWA対応）。追加後は、YouTubeやTikTokアプリの共有メニューから「リピごち」に直接URLを送れます。
- [夜ごはんタイプ診断](https://165cm.github.io/matagochi/?quiz=1)では、料理写真8枚と価値観の二択9問に回答。3軸の組合せで動物キャラクターと献立の楽しみ方を表示し、画像で共有できます。好み・時短・常備品の活用は献立の加点に反映します。
- 調味料は公開調査をもとに定番9品を「ある」で初期選択。違うものだけタップして変更できます。既存の回答は保持します。
- 初回は16画面で人数・好み・調理器具・調味料などを設定します。不明な項目は保留でき、途中で閉じても続きから再開できます。
- 「献立」で3日分（7日分へ切り替え可能）を確認し、気に入ったら確定します。条件に合う候補がない場合は設定を調整してください。
- 「買い物」は確定した献立の材料だけを表示。「買う」「家にある」「購入済み」で整理できます。
- 「今日」から作り方を開いて、食べたら「作った」。写真・メモ・また食べたい気持ちは「ふりかえり」で残せます。
- 「レシピ」からURL・画像・手入力で追加できます。YouTubeの公開・限定公開の再生リストURLを貼ると、動画をまとめて夜ごはんのレシピに追加し、献立の候補にします（1回200本まで、「後で見る」「高評価」は対象外）。材料は説明文から自動で拾い、作る日に「作り方」画面から1品ずつAIで整えられます。材料・手順はいつでも編集でき、調理条件を設定すると自分向け提案にも使えます。
- 右上の「設定」で食生活の設定、家族メンバー、JSONバックアップ、合言葉同期を管理できます。設定済みの項目は一覧から直接変更できます。
- 既存データは引き継ぎます。これまでの候補は未確定なので、最初に献立を確認してください。

## できること

- Instagram / Facebook / TikTok / YouTube Shorts のURL判定
- ホーム画面追加（PWA）とオフライン表示
- SNSアプリの共有メニューからのURL受け取り（ホーム画面追加後）
- YouTube / TikTok の動画サムネイル表示
- TikTok動画のタイトル・サムネイル取得（oEmbed）
- Cloud Run API設定済み環境でのYouTube説明文取得
- Gemini FlashによるYouTube説明文からの材料メモ作成
- スクリーンショット・画像最大5枚からのAI下書き作成（JPEG/PNG/WebP、確認して保存、API設定済み環境）
- キャプション貼り付けからの材料・調理方法の抽出
- 元レシピの人数に基づく1人分・2人分への換算（人数不明は換算せず表示）
- 登録・編集画面での材料メモ調整と取得時データへの復元
- 保存済みレシピの検索・編集・削除
- 家族別のリピ周期記録（前回の周期を初期値に）
- 夜ごはん1日1品の3日・7日提案、確定・入れ替え・自炊のお休み
- 確定した今夜の料理を「作った」で1タップ記録
- 確定した献立の買い物リスト（常備品の除外、購入済み、手動追加、コピー・共有）
- 料理写真の登録（任意）とリピ記録履歴の削除
- 家族メンバーの追加・名称変更・削除
- 合言葉だけの端末間同期・家族共有（アカウント登録不要、Cloud Run API設定済み環境）
- JSONファイルによる手動データ連携とバックアップリマインド
- 設定画面からのレシピ・リピ記録の全件削除／全データ削除

データはこの端末のブラウザ（IndexedDB）に保存されます。旧バージョンのlocalStorage保存分は初回起動時に自動で引き継ぎます。端末を変えるときは、JSONバックアップの書き出し／読み込みで移すか、設定画面の合言葉同期でつなげます。合言葉同期を使うと、レシピ・リピ記録・器具・常備品・確定献立・買い物はサーバー（Cloud Storage）にも保存されます。合言葉を知っている人はだれでもそのデータを見たり変えたりできるので、ほかの家庭とかぶらない推測されにくい合言葉を使い、住所などの個人情報は保存しないでください。

個人の食材制限・好み・初回設定の下書きは合言葉同期では共有しません。JSONバックアップには含まれます。

YouTube連携は動画の説明文を使います。字幕トラックの取得はできません。
Cloud Run APIを設定していない環境では、これまで通りキャプションを貼り付けて材料メモを作れます。

## 開発メモ

YouTube説明文取得APIと合言葉同期APIは `api/` にあります。Cloud Runで動かす場合は `api/.env.example` を参考に、YouTube Data APIキーとGoogle Cloud / Vertex AIの設定を環境変数で渡します。合言葉同期を有効にするには、保存先のCloud Storageバケットを作成して `SYNC_BUCKET` を設定します。
フロント側では `window.MATAGOCHI_API_BASE_URL` にCloud RunのURLを設定すると「URLから取得」と「家族と同期・共有」が有効になります。

## 1人・2人暮らし向けMVPの改修

夜ごはんの単品料理に集中します。朝食・昼食・副菜・汁物の保存データと履歴は残し、週間献立の自動候補は `mealType=dinner` に絞ります。初期メンバーは「自分」1人、表示人数は1人・2人をすぐ選べます。

YouTube取り込みは投稿IDで共通の分析結果を再利用します。編集は端末／同期ルームの保存内容にだけ反映し、共通DBは明示的な修正提案と管理者承認で更新します。共通版の比較と任意取り込みも可能です。AI分析には保存先設定が必要です。設定と運用は `api/README.md`、更新ルールは `docs/RECIPE_DB_POLICY.md` を参照してください。

```sh
npm ci --prefix api
npm test --prefix api
node --test test/*.test.cjs
```

新しい画面の確認手順と開発者向けの検証方法は [毎日の食生活UX](docs/DAILY_UX.md) を参照してください。
