# リピごち：迷わず残せる、料理ノート

対象は1人・2人暮らし。献立の品数を増やすより、「おいしそうと思った1品を残す」「今夜作る1品を決める」を短くする。

## 体験の原則

- 各画面に主目的を1つ。登録は「方法を選ぶ→内容を確認→保存」の順。
- リンク／画像／手入力は同時に説明せず選択式。材料を確認する前に保存を促さない。
- 出典・タグ・本文の編集、共通版の比較・修正報告は折りたたむ。入力値や既存機能は保持する。
- 処理状態は操作したボタンの近くに表示する。失敗時は理由と次の操作を残し、トーストだけに依存しない。
- 編集中のデータをAIで上書きしない。内容に変化がない入力イベントは編集と誤判定しない。

## 見た目

温かいアイボリー、深いグリーン、余白、丸みのあるカードを共通の基準にする。メニューの説明より料理名と写真を強く見せる。複数の統計を最初に並べず、1品への入口を優先する。

SNSで共有されたときにも「自分の料理ノート」と伝わる見た目を目指す。流行を断定した装飾や過剰なバッジは増やさない。拡散の保証はしない。写真付きの記録カードや共有用画像の生成は今後の追加機能とし、今回の改修では生成・公開しない。

## 比較画面

全文の左右比較をやめ、変更点を先に表示する。自分だけの内容はオレンジと「− 自分だけ」、共通版だけの内容はグリーンと「＋ 共通版だけ」。同じ内容は折りたたみ内に置く。色覚だけに頼らず文字でも区別する。材料を1行挿入しても後続すべてを変更扱いしない。

## 幅と操作

アプリ本体の幅でレイアウトを考える。PCの広い画面内でも430pxのアプリに横長フォームを入れない。材料名は1行、分量操作と削除は次の行へ。入力欄は縮小可能にする。主要操作のタッチ領域は44px以上を基本とし、キーボードフォーカスを明示する。

## 今回と今後

今回は登録導線、人数・材料編集、差分比較、解析状態の見える化、共通の色・カード・余白を更新する。献立・リピ記録・設定の情報構造の全面変更、ネイティブアプリ化、SNS投稿・自動拡散は実施しない。PWAとしてホーム画面から使う既存構成を維持する。
