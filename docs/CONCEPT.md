# リピごちのコンセプトと改善計画（2026-09-24）

## はじまり

父と娘のふたり暮らし。「今日は納豆パスタでいい？」に「パスタは一昨日食べたじゃん」と返された夜が出発点。
おいしいもの・体にいいものを作ってあげたいのに、何をいつ食べたかまでは覚えていられない。

## 解きたい課題

**「また〇〇なの？」をなくすこと。** ただし、この言葉はネガティブなので画面やLPでは使わず、
**「かぶらない、飽きない、また食べたい。」**という前向きな約束で表現する。

「また」には2種類ある。

| 飽きる「また」 | うれしい「また」 |
| --- | --- |
| 最近と同じ系統が続く（パスタ→パスタ） | 好物が、恋しくなった頃にまた出てくる |
| 片方だけが好きな料理が続く | ふたりとも好きな一皿 |

リピごち（リピート＋ごちそう）は、前者を減らし、後者を増やすアプリ。

## 対象

- 本来の対象：食卓を共にする2〜4人の世帯（親子、カップル、夫婦）
- MVP：ひとり暮らし〜ふたりまで（好みの最適化を2人までに限定）

## 現状のコードで足りないこと（2026-09-24時点）

1. **最近食べたものが献立に反映されない場合がある**：「作った」だけで「また食べたい」を押していない料理は、`getRecipeRepeatSummary` で未記録扱い（`preferencePending` を除外）になり、2日前に作った料理がすぐ再提案されうる。
2. **系統のかぶりを見ていない**：`Lifestyle.propose` は同じレシピの重複しか避けない。主食（麺・ごはん・パン）、主菜（肉・魚・卵豆腐）、味（和洋中）の連続は考慮していない。
3. **「また食べたい」が1人分だけ**：`life-again` / `life-frequency` は `state.family[0]` にだけ記録する。ふたり目の好みが残らない。
4. **前回いつ食べたかが見えない**：カードや入れ替え候補に「前回は◯日前」がない。
5. **苦手・制限が世帯で1つ**：メンバーごとの苦手を持てない。

## 改善計画（優先度順）

| # | 内容 | 実装メモ |
| --- | --- | --- |
| 1 | 作った記録は評価前でも「最近食べた」として扱う | `evaluations` の `cookedAt` を直近履歴として使い、N日以内に作った料理は候補から外すか大きく減点 |
| 2 | 系統のかぶり防止 | レシピに `staple`（麺/ごはん/パン/その他）と `protein`（肉/魚/卵・豆腐/なし）を付与（材料と主食カテゴリから推定）。直近3日＋献立内で同じ系統が続くと減点。理由表示は「一昨日はパスタだったので、ごはんもの」 |
| 3 | ふたりの「また食べたい」 | 「作った」後、メンバーごとに😍/🙂/🙅をワンタップ。スコアは2人の合計、どちらかが🙅なら候補から外す |
| 4 | ちょうどいい頃に、また | 既存のリピ周期（毎週・月2回…）をメンバーごとに持ち、周期に近づいた好物を上位へ。「久しぶり」ラベル |
| 5 | 前回からの日数を表示 | 献立・入れ替え・レシピに「前回は5日前」「はじめて」 |
| 6 | メンバーごとの苦手 | 世帯の食べられない食材（安全）と、個人の苦手（好み）を分ける |
| 7 | リクエスト | 家族が「これ食べたい」を送れる（合言葉同期のルームを利用） |
| 8 | 3〜4人へ拡張 | MVP後。好みの集約ルール（全員OK優先、誰か🙅は除外）を一般化 |

## 言葉づかいのルール

- 「また〇〇？」「かぶった」「飽きた」を画面に出さない。
- 代わりに「かぶらないように」「久しぶり」「ふたりとも好き」「前回は◯日前」。
- 評価は責めない言葉で（🙅も「今回はパス」）。

## 進み具合（2026-09-24 更新）

- 1〜5・7 は実装済み。評価は「次に食べたい頃（周期）」の1種類に統一し、献立のロジックは `docs/APP_MAP.md` にまとめた。
- 7 のリクエストは、合言葉同期のルームを使った招待リンク方式で実装（アカウント登録なし）。
- 次の候補：6（メンバーごとの苦手）、献立条件の家庭共有、リクエストの通知。
