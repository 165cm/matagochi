## 2. 問題・変更後・含めない範囲
**問題**（§4.2「16画面設定と21段階FUNNELを整理。重複質問・宣言・擬似進捗を見直す」「タイマーだけで100%になる現行演出は、実処理に対応した状態表示へ」）
- 「いま、夜ごはんはどうやって決めてる？」（`pain`）が、PR 1 の方針の会話の最初の質問「いちばん大変なのは？」と重なっていた
- 宣言（声に出して3回・指で長押し）があった
- 最後の「あなた専用の献立を、つくっています」は、80ミリ秒ごとに2%ずつ進むだけで、実際の処理と関係がなかった（`buildingLines` は「〜しています」と進んでいるふりの文）
- PR 1 の方針の会話は、今日の「やること」からしか開けず、初回設定には入っていなかった

**変更後**（`daily-ui.js` の `FUNNEL`：21 → 15画面＋方針の会話）
- 人数 → 一緒に食べる人 → 食べられないもの → 器具 → 平日の時間 → スキル → **方針の会話** → 新着から選ぶ → 動画 → 読んでみる → 1年で… → 叶えたいこと → リズム → 忘れないように → **この条件で、献立を作ります**
- 方針の会話は、PR 1 の画面をそのまま初回設定の中で使う（`talkInFunnel`）。聞き返し・確かめる・保存まで。「🔒 設定のまま」は、まだ保存していない初回設定の下書きの食べられないものを見せる（`talkFood`）。「方針はあとで（次へ）」で飛ばすと、会話は途中のまま残り、今日の「やること」から続きを開ける。最初の質問からの「戻る」は、前の設定の画面へ
- 最後の画面は、この時点で決まっている中身を並べるだけ（`resultLines`：人数と一緒に食べる人・入れない食材・平日の時間・道具とスキル・方針で「合ってる」にしたこと・選んだ料理）。タイマーも「〜しています」もない
- 「最初の提案を見る」：方針を保存した人は、最初の具体的な料理とその理由（§4.2「診断結果は無料。最初の具体的な料理と、その推薦理由まで表示」）。保存していない人は、これまでどおり献立タブ
- 途中まで進んでいた人：`migrateFunnel` が、以前の番号 → 同じ画面（なくなった画面は次に残っている画面）へ一度だけ移す（`onboardingDraft.funnelV = 2`。`Lifestyle.profile` はこの印を残す）

**やめたもの**：`pain`・晩ごはんタイプの5画面（割合・主食・お店・いちばん大事なこと・タイプ）・宣言・時間で進む「作成中」。晩ごはんタイプの計算（`cook-type.js`）は消していない（テストも残した）。方針の画面から任意で開けるようにするのは PR 2b

**含めない範囲（PR 2b）**：深掘りの質問（平日と休日・同居人との違い）、献立案への反応（「これだと作れそう？」「変えるならどこ？」）、方針の見える化（本人が言ったこと／記録からの傾向／次に試す提案・版の履歴）、共有範囲の選択、16画面の「詳しい設定」の整理
