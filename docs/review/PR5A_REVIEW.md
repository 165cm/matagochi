## 2. 問題・変更後・含めない範囲
**問題**：献立のリズムは「平日5日／1週間まとめて／3日ずつ」の3つで、どれも月曜はじまり・曜日は固定だった。§9 の「3日」（週1回の買い物で3食）がなく、週の始まり・作る曜日・買い物の日を選べなかった

**変更後**（`household.js`）
- `RHYTHMS` に日数（`sizes`）を持たせ、「3日」（`three`）を足した。表示名を §9 に合わせた（5日・3日＋3日・3日・1週間まとめて）。preset の ID は変えていない
- `state.rhythm.days`：作る曜日（0＝日〜6＝土）を週の始まりからの順に。`rhythmBlocks()` が preset の `sizes` で分けてまとまりにする（3日＋3日は前の3日／後ろの3日）。日数が合わない・同じ曜日・範囲外・数字でない値は `validRhythmDays` で捨て、以前の月曜はじまり（`blocks`）に戻す
- `blocksFrom`：まとまりの曜日の並びを、その日からの日付に（飛び飛びの曜日・週をまたぐまとまりにも対応。以前は「続けて N 日」だった）
- `state.rhythm.shopBefore: 0`：買い物の日をまとまりの初日に（ない時は前日＝以前と同じ）。`shopDayOf`
- 設定の「献立のリズム」：週の始まり（日〜土）・作る曜日（週の始まりから7日を並べ、1つずつ外す・足す。日数がそろった時だけ保存し、途中は「あと1日」）・買い物の日（前日／初日）。リズムの選択肢の下の説明は、選んでいるリズムなら実際の曜日（例：「月火木金土・週1回の買い物」）
- `applyRhythm`：リズムを変えた時の共通の処理（今日以降に決めた献立がなければ次の丸ごとの回から・下書きの入れ替えを消す。以前の `life-rhythm` と同じ）
- `daily-ui.js` の `rhythmReminder`：決める日の通知を、選んだまとまりと買い物の日に合わせる
- `app.js`：設定の一覧の行に「5日（月火木金土）・買い物初日17:00」
- 版：`APP_VERSION` `20261001-rhythm`・`CACHE_NAME` `ripigochi-v127`

**含めない範囲（PR 5b）**：後半の組み直し（前半の実績と本人が確かめた残りの食材から）・入れ替えで増えた／不要になった品を品名で示す（いまは件数の知らせだけ）・保存できる日数の扱い。無料／プラスの出し分け（§9「無料：毎日の今夜1品」）は PR 7（`GATING_LIVE` はオフのまま）

### あわせて直したこと（CI で見つかった、PR 2c のタイミングの問題）
- 1回目の CI で、公開済みの PR 2c のテスト「review fix (PR 2c): after an old app drops sharedPolicies…」が1回だけ失敗した（手元では8回とも成功）。原因：速い機械で「見せる」→「見せない」が同じミリ秒に書かれ、`updatedAt` が同じになり、同期の組み合わせ（`mergeShared`）の同点の決め方（文字の並び）で古い「見せる」が勝っていた
- 直したこと：`publishTalkPolicy` は、前の記録より必ず後の日時を書く（同じか前なら +1 ミリ秒）。`mergeShared` は同じ日時なら「見せない」を優先（見せすぎない側）。時計を止めて必ず再現するテスト「fix (found by CI)…」を追加（修正前は失敗）
- 変えたファイル：`talk-ui.js`・`profile-talk.js`・`test/profile-talk.test.cjs`
