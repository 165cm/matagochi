## 2. 問題・変更後・含めない範囲
**問題**：方針（本人が確かめた好み）は、答えた時のまま。記録（「また食べたい」）で分かってきたことは「📈 記録から見えてきたこと」に文で出るだけで、方針や献立につなげる道がなかった

**変更後**
- `profile-talk.js`
  - `THEMES`：テーマ（魚・さっぱり・ピリ辛・こってり・甘辛・15分以内・材料が少ない）と、採用した時に ✓ にする方針（`lean`）
  - `evidence(p, member, { evaluations, recipeOf, today, limit })`：最近90日の記録を `Lifestyle.latestRatings`（料理×人の最新）で見て、その人の評価だけで数える。add（3品以上・「また食べたい」2品以上かつ6割以上・方針が ✓ でも ✕ でもない。**いまの答えから外れた ✕ も尊重**）／drop（方針が ✓・3品以上・「また食べたい」0品・「月1回／しばらくいい／もう作らない」2品以上）。根拠の文 `note` と料理名 `names`（3つまで）
  - `adoptEvidence`：テーマと方針の組が正しい時だけ、方針を ✓／✕（`via: "evidence"`）にして版を1つ残す（`reason: "evidence"`・`note`）
  - `skipEvidence`：方針は変えず、その時の品数を `evidence` に覚える（2品増えるまで聞かない）
  - `decide`：`via` に `evidence` を足した（`react` と同じく、答えを直しても消えない）。`interpret` の `source: "records"`
  - `normalize`：`via`・版の `reason: "evidence"`・`note`（80文字）・`evidence` を検査して残す
- `talk-ui.js`：`talkEvidence`・`renderTalkEvidence`・`renderReflectEvidence`・`talkEvidenceAnswer`（`life-talk-evidence`。**ボタンの値は信じず、いまの記録から作り直した提案の中から選ぶ**。会話 `session` を作らない。家族に見せている時は `publishTalkPolicy`）。方針の画面：「（記録から）」の印・履歴に「記録から」と根拠。「答えを消す」で `evidence` も消す
- `daily-ui.js`：ふりかえり（今月）に1件
- `styles.css`：`.evidence-card` ほか
- 版：`APP_VERSION` `20261001-evidence`・`CACHE_NAME` `ripigochi-v134`

**含めない範囲**：AI での読み取り（この版もAIは使わない）・テーマの追加（野菜・煮込みなど、判定の確かな印がないもの）・計測イベントの新設（採用は既存の `talk_fixed`。「過去の記録からの再調理」の計測は API の `USAGE_EVENTS` を変えるので別に）

## 3. 受け入れ条件
- 根拠つき：品数と料理名を出す。優劣の言葉を使わない
- 本人が採用・見送り：自動で方針を変えない。見送りは同じことをすぐ聞かない
- 方針の版に理由（記録から・根拠の文）を残す
- 家族の片方だけの新しい記録で、もう片方の評価を落とさない（人ごとの最新）
- 本人が ✕ にした方針は勧めない
- 見ているだけの人・書きかえたボタンでは方針を変えられない
