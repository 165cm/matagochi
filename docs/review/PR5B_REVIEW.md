# PR 5b レビュー資料（Codex 向け）：買い物の差分を品名で・残っている食材で後半を組み直す

指示書：`docs/PERSONALIZE_PLAN.md` §9（「後半は前半の実績と利用者が確認した残り食材で組み直せる。使ったはずとAIだけで在庫を断定しない」「購入済みチェックを維持し、入れ替えで増えた／不要になった品を示す」「確定済み献立を新着で勝手に置換しない」）。仕様：`docs/APP_MAP.md` §14（今回追記）。

## 1. 対象
- ブランチ：`claude/optimistic-albattani-jg5211`（#106 の公開後、最新の `main` `c333c72` から作り直した）

## 2. 問題・変更後・含めない範囲
**問題**
- 献立を入れ替えると買い物リストの差分を数えていたが（`shoppingNotice`）、**画面のどこにも出ていなかった**。品名も分からず、買ったあとに入れ替えた時に「もう買ってあるのに使わなくなった品」も分からなかった
- 前半に作らなかった料理の材料や、残っている食材を後半の献立に生かす方法がなかった（端末ごとの「使い切りたい食材」はあるが、家族で共有されず、買い物の流れの中にない）

**変更後**
- `daily-ui.js`
  - `changedShopping`：差分を品名で持つ（`added` 買う物に増えた・`removed` いらなくなった・`bought` 買ってあるのに使わなくなった・`more` 買ってあるが分量や使う料理が変わった）。短い知らせと、買い物タブの上の表示（`renderShopDiff`、×で閉じる）。「残っている食材に入れる」
  - 残っている食材：`state.leftovers`（`setLeftover`・`activeLeftovers`＝確かめてから7日以内）。候補（`leftoverCandidates`）は「ここ7日で買った印があるのに、今のリストで使わなくなった品」と「前の買い物のあとに予定していたのに作らずに過ぎた料理の材料」（常備品で「ある」・水などは出さない）。**候補は押すまで使わない**
  - 献立タブの「🧺 家に残っている食材」（前に買い物完了をしたことがある時）：候補を押して選ぶ・入力で足す・「🧺 この食材で組み直す」＝**まだ決めていない日の入れ替え（`planOverrides`）だけを消して作り直す**（`undecidedPlanDates`：確定・作った・お休み・始まる前の日は入れない）
  - 買い物リスト：残っている食材の品は外さず「🧺 残りあり」
  - `dailyProfile` に `leftovers`
- `lifestyle.js`：`profile` に `leftovers`。`fit` で残りの食材を使う料理に＋20（「使い切りたい食材」と両方でも1回）、理由「🧺 残りの◯◯を使う」。食べられない食材などの条件は変えない。`shoppingName`・`isBought` を外から使えるように
- `app.js`：`state.leftovers` の保存・読み込み（`normalizeLeftovers`：名前30字・30品まで・何度通しても同じ）・同期（まるごと新しいほう）
- 版：`APP_VERSION` `20261001-leftover`・`CACHE_NAME` `ripigochi-v129`

**含めない範囲（PR 5c）**：保存できる日数（まとめ買いでも傷みやすい食材を後半の買い足しへ）・人数を変えた時の買った分の扱い

## 3. 受け入れ条件（§14）
- 使ったはずと決めつけない：候補は押すまで使わない・作った料理から自動で減らさない・7日で外れる
- 確定済み献立を置き換えない：組み直しは決めていない日だけ（テスト）
- 購入済みを保つ：買った印は変えない。使わなくなった品は「買ってある」として出す
- 条件をゆるめない：加点だけ（テスト：食べられない食材の判定は残りの食材があっても同じ）

## 4. テスト
- `node --test test/*.test.cjs`：198件 成功（194件＋`test/leftovers.test.cjs` 4件：加点と条件／入れ替えの差分と「残りに入れる」／候補・7日・形の検査・同期／組み直しで確定の日は変わらない・残りを使う提案・リストの「残りあり」）
- `npm test --prefix api`：141件 成功（API は変更なし）
- `node --check`・`git diff --check`
- Playwright（API はモック）：390×844・844×390・1440×900 で、1品を買った印にしてから入れ替え → 買い物タブの差分 → 「残っている食材に入れる」→ 献立タブの「家に残っている食材」→ 入力で足す → 組み直し。ページのエラー・横スクロールなし。画像は `docs/review/pr5b/`

## 6. 影響
- 保存・同期：`state.leftovers` を足した（家族の同期に入る）。**古い版のアプリは、書き戻す時にこの項目を落とす**（新しい版の端末が次に同期した時に戻る。サーバーでの引き継ぎは `sharedPolicies` だけ）
- 献立：残っている食材を選んだ時だけ、加点が変わる。確定した献立は変わらない
- API・AI の費用：変更なし

## 7. コードだけでは完了できないこと
- 残っている食材を何日で外すか（いまは7日）・加点の大きさ（いまは「使い切りたい食材」と同じ＋20）

## 8. ロールバック
- revert で戻る。残った `leftovers` は古い版では無視される
