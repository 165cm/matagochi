# レビュー資料（Codex 向け）：掲載停止の2段階化・投稿者向けの断定表現の修正

指示書：`docs/PERSONALIZE_PLAN.md` §8・§12-4・§12-5・§16。仕様：`docs/APP_MAP.md` §38。PR 3 の先行分①。

## 1. 対象
- ブランチ：`claude/creators-takedown`（`main` `b2f7b14` から。PR 1〜他のPRには積んでいない）
- 対象コミット：PR のコミット一覧を参照

## 2. 問題・変更後・含めない範囲
- **問題**：フォームを送れば誰でも、どのチャンネルでも、その場で停止が確定していた（持ち主の確認なし）。投稿者向けページが「再生は皆さまの再生として数えられ…収益も皆さまに届きます」と断定していた
- **変更後**：申し込みは「確認待ち（一時的に外す）」。管理者が `confirm`（確定）か `restore`（戻す）を決める。戻したチャンネルへの確認前の申し込みは記録だけ。以前の版で外したチャンネルは確定扱いで外したまま。ページは断定をやめ、アプリ内の数は YouTube 公式の数字と別と明記
- **含めない**：持ち主の確認（投稿者が自分のチャンネルだけを管理）、参加申請、修正依頼、動画単位の停止、管理画面（いまは API のみ）→ PR 3 本体

## 3. 満たした受け入れ条件（§14）
- 未確認の許諾・投稿者を、公開可・本人確認済みにできない：公開ルートは確認待ちにしかできない（送られた `status`・`decision` は無視）→ `api/test/creators.test.js`
- 掲載取り消しが推薦に反映：確認待ち・確定は `optedOut()` に入り、新着・みんなの定番・似たレシピ探しから外れる（既存の trends テストも通過）
- 同時の申し込みで片方を失わない（世代番号つきの書き込み）

## 6. 影響
- 保存形式：`creators/optout` に `pending`・`restored` を足した（`channels` はそのまま）。古いサーバーが読むと `pending` は無視され、確認待ちのチャンネルが出てくるだけ
- API：`POST /api/creators/request` の答えに `status` を追加（`removed` は残す）。管理ルート2つを追加（`RECIPE_ADMIN_TOKEN`）
- AI原価・同期・アプリ：影響なし

## 7. コードだけでは完了できないこと
- 確認待ちの申し込みを誰がどう確かめるか（運営の手順）。いまは管理者が `curl` で `GET /api/admin/creators` → `POST …/decide`
- 投稿者向けページの文言の最終確認（ユーザー）

## 8. ロールバック・既知の制約
- revert で戻る。確認待ちのチャンネルは、以前の版では外れない（`pending` を読まないため）ことに注意
- 確認待ちの間は、第三者の申し込みでも一時的に外れる（害は「新着・定番に出ない」だけ）。同じ第三者が戻したチャンネルを繰り返し外すことはできない
