# PR 5c レビュー資料（Codex 向け）：傷みやすい食材の「その前に買うと安心」・あとで買う・人数の変更

指示書：`docs/PERSONALIZE_PLAN.md` §9（「5日分のまとめ買いでも保存可能日数を推測で保証しない。確認済みの保存情報を使い、不明なら後半の買い足しへ」「購入済みチェックを維持」「人数変更」）。仕様：`docs/APP_MAP.md` §14（今回追記）。

## 1. 対象
- ブランチ：`claude/shop-freshness`。**PR 5b（#107・`claude/optimistic-albattani-jg5211` `6d4ae80`）の上に重ねた**。5b と同じ買い物のコードを触るため。この PR の差分は 5b の後の分だけ（PR の比較先は 5b のブランチ）。5b がマージされたら、比較先を main に変える

## 2. 問題・変更後・含めない範囲
**問題**：まとめ買い（5日・1週間）で、後半の日に使う傷みやすい食材も、買い物の日に一緒に買う前提のリストだった。何日もつかの確かな情報はアプリにない（`Lifestyle.freshness` は急ぎ度の表で、日数ではない）

**変更後**（`daily-ui.js`）
- `freshLater(item)`：買う物のうち、傷みやすい食材（急ぎ度5は2日目から・4は3日目から・3は4日目から）を、買い物の日（リズムのまとまりの買い物の日。過ぎていれば今日。リズムがなければ今日）から何日も後に**初めて**使う時だけ `{ date, label }`。冷凍品・缶詰など（`KEEPS`）・手入力の品・急ぎ度2以下は対象外。1つでも早い日に使う品は対象外（今回買う）
- 買い物リストの品の下に「🗓 10月4日（日）に使う・傷みやすいので、その前に買うと安心」。**何日もつとは書かない**。「あとで」ボタン
- `life-shop-later`：本人が押した時だけ、その品の買った印を `later`（今回の買い物から外す。「家にある」ではない）にし、「もやし（10月4日の分）」を手入力の品として足す（買い物完了の後も残る）。「あとで買う」の欄。元に戻せる（`shopUndo`）
- `app.js`：買った印の形に `later` を足した（`normalizeShoppingMarks`）
- 人数を変えた時：買った印は残り、量が変わった品は「要確認」（以前からの動き。テストで確認）
- 版：`APP_VERSION` `20261001-later`・`CACHE_NAME` `ripigochi-v131`

**含めない範囲**：食材ごとの保存日数のデータ（確かな情報がないので持たない）・冷凍のすすめ（§3 の持ち越しには以前からある）

## 3. 受け入れ条件（§14・§9）
- 保存可能日数を推測で保証しない：日数を書かず「その前に買うと安心」とだけ知らせる・自動で外さない
- 購入済みを保つ：「あとで」は買った印を「購入済み」にも「家にある」にもしない。人数を変えても買った印は残る
- 買い忘れない：「あとで」の品は日付つきで買い足すものに残る。古い版のアプリは `later` を「買う」として扱う
