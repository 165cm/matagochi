# レビュー資料（Codex 向け）：新着の「集める」と「見せる」を分ける

指示書：`docs/PERSONALIZE_PLAN.md` §7.3・§12-2・§12-3・§12-7・§16。仕様：`docs/APP_MAP.md` §39。PR 3 の先行分②。

## 1. 対象
- ブランチ：`claude/trends-collect-display`（`main` `b2f7b14` から。ほかのPRには積んでいない）
- 対象コミット：PR のコミット一覧を参照

## 2. 問題・変更後・含めない範囲
- **問題**
  1. 週の初めに10品そろうと、その週の新着集めが止まっていた（表示枠と収集が同じ数）
  2. `GET /api/trends` の中で、キャッチコピーを AI に書かせていた（閲覧で有料のAI処理が起きる）
  3. `GET /api/trends`・`GET /api/popular` が `catalog.import` を呼んでいた。保存がない・読み取りの版が古い動画は、閲覧で AI の読み取りが走り得た。`/api/popular/event` は誰でも送れるので、未読の動画を並べて閲覧でAIを動かすことができた
  4. 説明文の30日ルールの取り直し（YouTube API）が、閲覧のついでに行われていた
- **変更後**：集める（定期実行）＝1日2品・1週14品まで（環境変数で変更可）、新しい日はチャンネルの新着を見直す、後片付け（説明文の取り直し・アイコン・キャッチ）も1日1回ここで。見せる（GET）＝`catalog.peek` で保存済みを読むだけ、1週10品まで新しい順
- **含めない**：`/api/trends/refresh` の認証（GitHub の秘密の値の設定が必要）、WebSub、非公開・削除・埋め込み不可の検知（`videos.list` の status）、投稿者の許諾による公開可否の管理 → PR 3 本体・PR 4

## 3. 満たした受け入れ条件（§14）
- 一覧GETだけで新規の有料AI処理が発生しない：trends・popular とも（`api/test/trends.test.js`）
- 「今週10品」の表示上限と日々の収集を分離・毎日必ずは保証しない（同）
- 失敗を成功扱いしない：AIの枠で止めた時は `done: false`（同）
- 重複防止・排他：既存の `trends/lock`・既出の動画IDの除外をそのまま使う
- ユーザーの取り込み用予算を使い切らない：既存の「1日のAI上限の半分まで」をそのまま使う

## 4. テスト
- `npm test --prefix api`：104件 成功（前は100件。trends 3件・recipeCatalog 1件追加。既存の trends テスト5件は「1回で10品」を前提にしていたため、`perDay: 10` を渡す形に直した）
- `node --test test/*.test.cjs`：144件 成功（アプリは変えていない）
- 画面：アプリの見た目は変わらないので、画面確認はしていない（答えの形は同じ）

## 6. 影響
- **AI原価**：集める上限が週10品 → 14品（最大＋4回/週）。`TREND_WEEK_MAX=10` で以前と同じ。閲覧からのAI処理はなくなる
- **YouTube API**：チャンネルの新着確認（安い呼び出し）が週1回 → 毎日。キーワード検索（高い）は以前と同じく週3組まで
- **保存形式**：`trends/index` の週に `day`・`byDay`・`channelScan`・`kw` を足した（`rounds` も残す）。以前の形の週は `kw = rounds - 1` として読む。`trends/icons` を新設
- **API**：`GET /api/trends`・`/api/popular` の答えの形は同じ。`POST /api/trends/refresh` の答えに `day`・`today`・`catches` を足した
- **アプリ・同期**：影響なし

## 7. コードだけでは完了できないこと
- 既定の数（1日2・1週14）でよいかの判断（ユーザー）。変える時は `gcloud run services update matagochi-api --update-env-vars TREND_WEEK_MAX=10` など
- デプロイ後、最初の数日は `/api/trends/refresh` の答え（GitHub Actions のログ）を確かめる

## 8. ロールバック・既知の制約
- revert で戻る。新しく足した項目は古い版では無視される
- 公開したばかりの時点で、キャッチのない料理はキャッチなしで表示される（翌日の定期実行で付く）
- 説明文が30日より古い料理は、取り直すまでの間、説明文なしで表示される（以前は閲覧時に取り直していた）
