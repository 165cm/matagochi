## 2. 問題・変更後・含めない範囲
**問題**
- 方針は常に「共有しない」で、2人で使っていても相手の方針が献立に効かなかった（PR 2b の「一緒に食べる人と好みがちがう」は「相手が自分の端末で答えます」と言うだけ）
- 家族共有とAIへの送信を別々に選ぶ仕組みがなかった（`share: { family:false, ai:false }` の固定値）
- 晩ごはんタイプ（PR 2a で初回設定から外した）を開く場所がなかった

**変更後**
- `profile-talk.js`
  - `share` を人ごとに：`{ 名前: { family, ai, at } }`。以前の固定の形は「だれも選んでいない」として空に。`shareOf`・`setShare`
  - `familyItems(p, member)`：家族に見せるのは ✓ の解釈IDだけ（推測・✕・答え・ひとことは入れない）
  - `normalizeShared`（届いた `sharedPolicies` の検査：一覧にないID・形の違う値を捨てる、12人・30件まで）・`othersFrom`（自分・止めた人・家族の名前にない人を除く）
  - `leaner(p, member, others)`：家族の ✓ を自分と同じ重みで加点（同じIDは1回、上限は同じ、休日だけの項目は土日だけ）。理由は「💬 はなこ：早くできる」。自分の ✓ が先
  - `interpretWithAi`：本人が「AIに送る」を選んでいない（`share[名前].ai !== true`）と AI を呼ばない（`error: "not_allowed"`）。この版は画面で選べない＝送らない
  - `session.stage: "type"`・`typeStep`（0〜4）を通す
- `app.js`：`state.sharedPolicies` を保存・同期（`buildSyncPayload`・`mergeSyncPayloads` は人ごとに新しいほう・両方を正規化してから・`applySyncPayload` で正規化）。`tasteProfile` 自体はこれまでどおり同期しない
- `daily-ui.js`：`preferenceOf` に家族の見せている方針を渡す
- `talk-ui.js`
  - 方針の画面に「👥 共有の範囲」：家族に見せる（見せない／見せる）・AIに送る（送らない・この版は選べない）。つながっていない時は「まだ届きません」
  - 「👨‍👩‍👧 家族が見せている方針」（読むだけ）
  - `publishTalkPolicy`：方針の操作のたびに、見せている人の ✓ を `sharedPolicies` に書く（変わった時だけ・その時だけ同期を予約）。「見せない」「答えを消す」は `{ on:false, items:[] }` を新しい日時で書いて家族の端末からも消す。一度も見せていない人は何も書かない
  - 「🎴 晩ごはんタイプ（おまけ）」：方針の画面から任意の4問 → カード →「この結果を残す」で `foodProfile` のタイプの答えだけを書きかえる（`tastes` などの献立の条件は変えない。初回設定の下書きを作らない）
- `cook-type.js`：`handleCookTypeAction(action, data, p = profileDraft())`（答えの入れ先を渡せる）。`life-priority` は初回設定の段がある時だけ進める
- `legal/privacy.html`：家族との共有の説明に1文（「家族に見せる」を選んだ時だけ方針を共有・答えとひとことは共有しない）。更新日 9月30日
- 版：`APP_VERSION` `20260930-share`・`CACHE_NAME` `ripigochi-v119`

**含めない範囲**：AIに送る を選べるようにすること（サーバーのAIをつなぐ時）、家族の方針を最初の提案（会話の中の提案）に使うこと（毎日の献立には使う）、YouTube・カタログ（PR 3 以降）

## 3. 満たした受け入れ条件（§14・§5）

- 家族共有とAIへの送信は別：`family` を見せるにしても `ai` は変わらず、AIは呼ばれない（テスト）
- 止めた時に相手の端末からも消える：新しい日時の `on:false` が勝ち、古い「見せる」で戻らない（テスト）
- 条件をゆるめない：加点だけ（`fit` はそのまま）。上限も同じ
- 旧データ・旧同期データ：`sharedPolicies` がなくても読める。`share` の古い形は空に。何度正規化しても同じ

## 6. 影響
- 同期：`sharedPolicies` を足した。古い版のアプリは書き戻す時にこの項目を落とすが、サーバーがいまの値を引き継ぐ（上の再レビュー①）。サーバーの更新の前にそうなった場合も、止めた記録（`on:false`）をほかの端末の古い「見せる」で上書きすることはない（②。見せている人の方針が、本人の端末が次に同期するまで一時的に見えなくなるだけ）
- API：`PUT` の同期（`putSyncRoom`）で、`sharedPolicies` がない書き込みに部屋のいまの値を足す。ほかの項目・形の検査は変えていない
- 献立：家族が「見せる」を選んだ時だけ変わる（加点のみ）
- AIの費用・API・権限：変更なし
- プライバシーポリシー：1文追加（下の §7）

## 7. コードだけでは完了できないこと
- **プライバシーポリシーの文言の確認**（ユーザー）：「家族との共有（同期）」の行に「『わが家のごはん方針』は、ご本人が『家族に見せる』を選んだ時だけ、献立に使っている方針を共有します。質問への答えや書いたひとことは共有しません」を追加した
- 家族の方針をどのくらい効かせるか（今は自分と同じ重み）の妥当性は、使われ方を見て判断

## 8. ロールバック・既知の制約
- revert で戻る。残った `sharedPolicies` は古い版では無視される（同期の書き戻しで消える）
- 方針は名前（`me()`）ごと。家族の呼び名を変えると、変える前の名前の方針は使われなくなる（見せ直すと新しい名前で入る）
- 晩ごはんタイプの途中の答えは、保存するまで端末のメモリだけ（読み込み直すと、段はそのまま・選びかけは保存済みの答えに戻る）
