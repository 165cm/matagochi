## 2. 問題・変更後・含めない範囲
**ユーザーの判断（2026-10-01）**：基本のレシピは YouTube から／同意のない動画は新着として28日・ランダムに見せる／献立に入れられたものはその人の保存に加えてみんなの定番にも残す／品数は採用率で決める／β版の集める費用は月1,000円まで

**変更後**
- `api/src/popular.js`
  - `kind: "shown"`（献立の候補に出した）を受け付ける。並べ方の重みは0。動画ごとに `shown`・`planned`・`cooked` を数える
  - `planned` の時、その動画がいま新着（`isTrend`＝28日以内の `trends/index`）なら `popular/kept` に残す（2,000本まで・競合時は世代つきで書き直し）
  - `top()`：数えた順位のあとに、残した動画を新しい順で足す（数が少なくても）。今までどおり `catalog.peek`（削除・非公開は null、30日より古い説明文は空）と掲載停止で外す。`kept: true`
  - `stats()`：この月と前の月の回数・採用率（planned ÷ shown）・残しているか
- `api/src/trends.js`
  - `list()`：28日以内のものすべてを、日ごとに決まるランダムな順（FNV で `日付|動画ID` を並べる。同じ日は同じ順）。以前は1週あたり新しい順に10品
  - 月の費用：AI を呼ぶたび（`spend`）に月の回数を足し、`trends/cost` に保存（12か月分）。`canSpend` に「月の回数 < 月の上限（円）÷ 1回の目安（円）」を足す。届いたら `limited: "trend_month_budget"`（done）。答えの `ai` に `month`・`monthCap`・`yen`・`yenCap`
  - `has(videoId)`・`cost()`
- `api/src/server.js`：`TREND_YEN_PER_MONTH`（既定1,000）・`TREND_YEN_PER_AI`（既定5）。`GET /api/admin/catalog`（管理の合言葉）：動画ごとの回数・採用率・残しているか・投稿者の「みんなが見る一覧」の同意、月ごとの費用、同意をお願いしたい投稿者
- `discover.js`・`daily-ui.js`：献立の画面で、新着・みんなの定番の料理が候補（決めた日でない・固定でない・休みでない）として出たら `shareShown`（同じ料理は1日1回・集計を止めた人・見ているだけの人は送らない）
- `legal/privacy.html`：みんなの定番の集計に「献立の候補に出た」と使いみち（残すかの判断）を追記
- 版：`APP_VERSION` `20261001-adopt`・`CACHE_NAME` `ripigochi-v139`

**含めない範囲**：採用率で残す・外す基準（PR 4c）・実際のトークン数での費用の計測・管理の画面（いまは API だけ）・投稿者への連絡（外部への勧誘はしない。一覧を出すだけ）

## 3. 受け入れ条件
- 一覧の GET で AI・YouTube API を呼ばない（`list`・`top`・`stats`・管理の一覧は読み出すだけ）
- 同意のない動画も、YouTube の30日の確かめ直し・削除や非公開での除外・掲載停止はそのまま守る
- 送るのは動画IDと好みのタイプだけ（料理名・記録は送らない）
- 月の費用の上限で止まる。止まっても「失敗」として毎回やり直さない
