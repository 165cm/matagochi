# レビュー資料（Codex 向け）：YouTube の情報の定期的な確かめ直しと削除（PR 3 の残り）

指示書：`docs/PERSONALIZE_PLAN.md` §8「保存期間と取り消し」・§7.3「定期更新・非掲載化」。仕様：`docs/APP_MAP.md` §41（新規）。

## 1. 対象
- ブランチ：`claude/youtube-refresh`（最新の `main` `7b9918a` から）。PR 2c（#101）・#102 とは別のブランチ。#101 と重なるのは `docs/*` の行だけ

## 2. 問題・変更後・含めない範囲
**問題**
- 読み取り結果の説明文・チャンネル名は「読み出された時」か「新着に出ている間」しか取り直さず、**読み出されない結果は30日を超えて持ち続けていた**（§8「読み出されないデータも残し続けない」）
- 取り直しに失敗しても日付だけ進め、30日間取り直さなかった
- **削除・非公開になった動画を見つける処理がなく**、一覧に出続け得た（§7.3「非掲載化」・§8「削除時、公開推薦を停止」）
- 「ほかの作り方」の検索結果（動画のタイトル・チャンネル名）は3日しか使わないのに、消していなかった。投稿者のアイコンもまとめて1つの日付で、古いものが残っていた

**変更後**
- `api/src/syncStore.js`：保存先に `list(prefix, { pageToken, max })` と `remove(key, { ifGeneration })`（メモリ・Cloud Storage）
- `api/src/youtube.js`：`fetchYouTubeStatuses(ids)`（50本で1回。なし＝削除、非公開、公開＋説明文など。通信の失敗は投げる＝「消えた」と扱わない）
- `api/src/recipeCatalog.js`
  - `sweep({ cursor, max })`：名前の順に max 件、25日より前に確かめた結果を確かめ直す。公開 → 取り直し。削除・非公開 → `unavailable: { reason, since }`（説明文・チャンネル名を外す）→ 30日たっても戻らなければ `remove`（読み取った材料・手順ごと）。確かめられない時は30日を過ぎた文字だけ外し、日付は進めない
  - `unavailable` の結果は `peek`（一覧）・`get`（共通レシピ）で出さない。`import` は AI を呼ばずに `video_not_found`／`non_public_video`（新着集めは「外す」扱いの既存のコード）
  - 読み出し時の取り直し（`refreshed`）：失敗しても日付を進めない。削除・非公開と分かったら `unavailable` に。`get` も30日を過ぎた文字を出さない
- `api/src/housekeeping.js`（新規）：1日1回（`housekeeping/state` を条件つきで書いてから）。カタログの sweep（1日200件・続きは次の日）・検索結果（`variant-search/*`）の4日を過ぎたものを消す（1日500件）・アイコンの30日を過ぎたものを外す。一部が失敗してもほかは進む
- `api/src/trends.js`：アイコンをチャンネルごとの日付つきで保存（`{ url, at }`）。読む側は以前の形（文字列）も読める（`pruneIcons`）
- `api/src/server.js`：`POST /api/trends/refresh` の結果に `housekeeping` を足す（GitHub の定期実行は `"done":true`・`"paused"` だけを見るので影響なし）

**含めない範囲**：動画が消えた時の `versions/*`（修正の審査の履歴）の片付け、回数の記録（YouTube の情報は入っていない）の片付け、端末に保存したレシピ（利用者のもの）、修正依頼の窓口（次の PR）

## 3. 受け入れ条件
- 対象の項目と期間を列挙した（APP_MAP §41 の表）
- 読み出されないデータも期間で見直す・削除や非公開で公開の推薦を止める・失敗を成功扱いしない（確かめられない時に日付を進めない）
- 一覧の GET で有料の処理を起こさない（後片付けは定期実行の中だけ）

## 4. テスト
- `npm test --prefix api`：132件 成功（123件＋9件：保存先の一覧と削除〔メモリ・Cloud Storage〕／状態のまとめ取り／sweep の公開・削除・30日後の削除・公開に戻る／確かめられない時／読み出し時／後片付けの1日1回・続き・検索結果・アイコン／アイコンの以前の形／定期実行の経路）
- `node --test test/*.test.cjs`（アプリ）：変更なし

## 6. 影響
- API のみ（マージで `deploy-api.yml`）。画面・同期は変更なし
- 保存先：Cloud Storage のオブジェクト一覧（1日数回）と削除を使う。サービスアカウントに削除の権限が必要（今の書き込み権限〔`storage.objects.create`〕に加えて `storage.objects.delete`・`storage.objects.list`）。**権限がない時は、後片付けのその部分が失敗として記録されるだけで、新着集めは止まらない**
- YouTube API：`videos.list` を1日最大4回（200件÷50）。検索は使わない
- AI：使わない

## 7. コードだけでは完了できないこと
- **Cloud Run のサービスアカウントの権限の確認**（ユーザー）：バケットに対して一覧・削除ができるか（「ストレージ オブジェクト管理者」なら可能）。できない場合、後片付けの結果に `{ error: "sync_storage_failed" }` が出る
- 25日・30日・4日の期間の妥当性（YouTube API の利用規約の読み方）

## 8. ロールバック
- revert で戻る。`unavailable` の印・アイコンの新しい形は、古い版でも読める（古い版は `unavailable` を知らないので、印のついた結果を一覧に出すことがある）
