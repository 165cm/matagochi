## 2. 問題・変更後・含めない範囲
**問題**：記録の画面は「食べた日・次はいつ・写真・メモ」だけで、何回作ったか・その日何人分だったか・元の動画が分からず、気に入った料理を献立にもう一度入れる道がなかった（献立タブで入れ替えるしかない）。ふりかえりの「わかってきたこと」の定番は1行の文だけ。
また、PR 5c で足した買い物の品ごとの「あとで」（`life-shop-later`）が、以前からある「買い物完了にする？」の「あとで」と**同じ操作名**だった（品の「あとで」を押すと完了のシートも閉じたことになる／完了のシートの「あとで」は id がないので品には効かないが、同じ名前の分岐を2回通っていた）。

**変更後**（`daily-ui.js`）
- `renderRecordFacts(d, r)`：記録の画面の料理名の下に
  - `cookHistory(recipeId)`：その料理の記録の数と日付（新しい順・4つまで）「🍳 3回つくった（9月28日・9月18日・9月5日）」
  - 「👥 この日は3人分」：記録の id が `meal-日付`（献立から記録した）の時だけ、その日の `mealSlots` の `servings`。手でつけた記録は出さない
  - 「▶ 元の動画（投稿者名）」：`videoUrl` がある時だけ（`rel="noopener"`）
  - 「🔁 もう一度、献立に入れる」（`life-replan`）：家族の画面を見ているだけの人・新しい記録を書いている途中・献立に使えない料理（`allDinnerRecipes` にない）には出さない
- `replanRecipe(id)`：
  - もう献立（確定・候補）に入っていれば `{ date, already: true }`（もう1日入れない。自分用に保存したコピー `starterId` も同じ料理として見る）
  - そうでなければ、今日以降でいちばん近い日のうち、休み・始まる前・固定された日（`lockedDates`）・確定／作った／休みの枠・**本人がほかの料理を選んだ日（`planOverrides` がある日）**を除き、`Lifestyle.fit` が ok の日に `planOverrides` で入れる（**下書き**。確定しない）。買い物の差分の知らせ（`changedShopping`）も出す
  - 入れる日がなければ `""` → 「入れられる日がありません…献立タブで入れ替えもできます」
- `stapleRecipes` / `renderStaples`：ふりかえり（今月を見ている時だけ）に「🏆 わが家の定番」。2回以上つくって、**いちばん新しい記録**でだれかが「明日でも／毎週」をつけた料理を、回数の多い順に6品まで。回数・前回の日・「🔁 もう一度」
- 買い物の品ごとの「あとで」の操作名を `life-item-later` に変えた（完了のシートの「あとで」は `life-shop-later` のまま）
- `styles.css`：`.record-facts`・`.record-links`・`.staple-card`・`.staple-list`・`.staple-photo`
- 版：`APP_VERSION` `20261001-records`・`CACHE_NAME` `ripigochi-v133`

## 3. 受け入れ条件
- 記録に作った回数・元の動画・人数が見える。人数は推測しない（献立の記録だけ）
- 再調理の導線：決めた日（確定・作った・固定）と、本人が選んだ下書きを置き換えない。条件に合わない日には入れない。同じ料理を2回入れない
- 家族の画面を見ているだけの人は献立を変えられない（ボタンも出さない・操作も効かない）
- 保存・同期の形は変えない（`planOverrides` は今までの形）
