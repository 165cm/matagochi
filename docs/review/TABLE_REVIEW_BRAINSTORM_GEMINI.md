# 「わたしの食卓レビュー」ブレスト回答（Gemini）

作成：2026-11-23（Gemini）

## 1. ひとことで

**「がんばりの採点」ではなく「わが家の食卓の物語（何が育ち、何がラクになったか）」を1枚のカードに仕立て、記録が2〜3回でも空振りせず、iPhone の Safari でも確実に画像保存・共有できるレビューにする。**

## 2. たたき台への評価

### 残すべき点（3つ）
1. **端末内計算＋Canvas画像生成（通信なし・0円）**：写真・料理名・家族名を外に出さない約束と月1,000円のAI予算を守りつつ、何回でも作れる。
2. **「リピと新顔の比率」と「次の献立へ1タップでつながる提案」**：「定番で安心しつつ飽きない」を数字で見せ、既存の `replanRecipe`（もう一度献立へ）や `planTune`（好みに寄せる）に直結できる。
3. **投稿前のプライバシー切り替え（写真／イラスト・料理名・家族名なし固定）**：食卓写真は生活感が出やすいため、公式イラスト（`cardArtOf` の48品イラスト等）へ1タップで差し替えられる設計は必須。

### 削るべき点（3つ）
1. **「野菜をしっかり使った日の数（分量が読めた料理だけ）」**：`estimateRecipeNutrition`（APP_MAP §67-2）は「元人数が未設定」「材料に1つでも適量・未辞書がある」と `vegG: null`（不明）を返す。実データでは多くの記録が「不明」で落ち、「野菜を食べたのに0日と出る」不満を生む。代わりに `Lifestyle.planBalance`（`BALANCE_VEG`）の**「使った野菜の種類数（分量不問）」**に絞るべき。
2. **「はじめて使った食材」**：古い記録（`state.evaluations`）の `recipeId` が削除等で引けない場合（`recipeOf` が `{ ingredients: [] }` にフォールバック）、過去の食材履歴が抜けて「前にも使ったキャベツが『はじめて』と出る」誤判定が起きる。親料理（`Lifestyle.sameDish`）基準の「はじめて作った料理」に留めるべき。
3. **「決めた夜のうち作れた割合（％）」と「連続◯週」**：週1〜2回の人や「作れなかった申告」（APP_MAP §81）をした人に「作れた割合 40%」「連続が途切れた」と見せると罪悪感になる。「作った回数」「決めた献立で迷わなかった夜の数」など**積み上げ（加算）だけ**を見せるべき。

### 危ない点（3つ：実データ・少記録・iPhone Safariの観点から）
1. **【画像生成】YouTubeサムネイルのCORS汚染で `canvas.toBlob` が落ちる**
   - 自分の写真（`e.photo` の Data URL）がない記録は、`cardImageInfo` が①承認イラスト（`assets/...` 同一オリジン）→②YouTubeサムネイル（`i.ytimg.com` 外部オリジン）の順に引く。外部画像を `<canvas>` に `drawImage` すると Canvas が汚染（Tainted）され、`toBlob()` / `toDataURL()` が `SecurityError` で即座に失敗する。
   - **対策**：Canvas に描く画像は**「本人の記録写真（Data URL）」または「アプリ内の承認イラスト（`assets/dishes/*`・`assets/dish-picks/*`・共通鍋イラスト）」のみに限定**し、YouTubeサムネイルはCanvasに使わない。
2. **【iPhone Safari】`navigator.share` のジェスチャー失効と保存形式の罠**
   - iOS Safari では、ボタン押下から `navigator.share({ files })` までに重い非同期処理（`document.fonts.load` や複数画像の `decode()`）が入ると `NotAllowedError` で共有シートが開かない。
   - **対策**：「画像プレビューを開く（この時点で Canvas → `Blob` / `File` 生成まで完了し保持）」と「📤 シェアする（保持済みの `File` を即 `navigator.share` へ渡す）」の2段階に分ける。出力は `image/png` または `image/jpeg` とし、Safari で `<a download>` が別タブ表示になった場合は「画像を長押しして『写真に保存』」と案内を出す。
3. **【実データ計算】`mealSlots` と `evaluations` のズレ・未回答評価の欠落**
   - `mealSlots` は古い日付が消えたり、献立を通さず記録だけ追加されたりするため、`weekReceipt` のように `mealSlots` から「使い回した食材」を数えると長期レビューで狂う。1週以外は `evaluations` を正本とし、`recipeOf(e)` の材料から集計する。また「また食べたい」は期間内の `e.familyRepeatCycles` だけ見ると「2回目の記録で評価を省略（未回答）」した時に消えるため、必ず `Lifestyle.latestRatings(state.evaluations)`（料理×人ごとの最新評価）で判定する。

## 3. 期間ごとの設計

全期間に全項目を出すと文字だらけになるため、**期間ごとに「主役1つ＋補助2〜3個」**に固定する。

| 期間 | 出す条件 | 主役の項目（いちばん大きく） | 補助の項目（2〜3個まで） | 見せ方・トーン |
|---|---|---|---|---|
| **1週** | 決めたor作った1食以上 | **🧾 今週のレシート**（決めた◯食・作った◯食・使い回し食材） | 😋 また食べたい料理／🃏 新規の図鑑カード／来週の約束 | 既存の「今週のレシート」（§73）を活かし、右下に「📤 画像にする」を追加 |
| **4週（月別）** | 3食以上（未満は「あと◯回で月報が出ます」） | **🔁 リピと新顔のバランス**（定番◯回・はじめて◯品）＋ **👑 今月の偏愛1品** | 🥩🐟🥚 主菜の帯グラフ（肉・魚・卵豆腐・野菜）／🥬 使った野菜◯種類 | 既存の月別表示（‹ 11月 ›）と統合し、1か月のリズムと発見を月報で見せる |
| **3か月** | 直近90日で6食以上 | **🍂 季節の食卓と育った定番**（旬の料理・新しく🏆定番／⭐常連になった料理） | 🎬 お世話になった作り手トップ3／🌈 彩りパレット（5色） | この季節によく食べたものと、わが家に定着した味を祝う |
| **半年（歩み）** | 累計5食以上（※1〜3か月の人向けに緩和） | **🌱 ここまでの歩み**（最初の頃の好物 vs 最近の好物・図鑑 ◯/48枚） | ⭐ 技★★〜★★★で作った回数／💑 ふたりの好みが重なった料理 | 半年に届かない人も「ここまでの歩み」として全期間の成長を見られる |
| **1年（2026年）** | 暦年に3食以上（年末特別枠） | **🏅 2026年のわたしの食卓アワード**（年間ベスト3の写真＋食卓タイプ） | 🍳 年間の作った回数・料理の種類数・野菜の種類数／🎬 年間の作り手・図鑑枚数 | 記録が3回でも「わが家の2026年トップ3」として華やかにカード化 |

## 4. 新しい項目のアイデア（たたき台にないもの・6つ）

すべて**端末内の既存データだけで確実に計算できる（AI・通信0円）**項目です。

1. **⚡ 「15分ごはん」に助けられた夜**：忙しい日も自炊できた自己肯定感を上げる。**データ**：`evaluations` → `recipeOf(e).planning.minutes <= 15`（または `Lifestyle.tags(r).includes("quick")`）の回数。
2. **♨️ 洗い物を減らした夜**：「ラクして作った日」を褒める。**データ**：`recipeCardSpec(r).easyTool`（`♨️レンジ` `✂️包丁なし` `🍳フライパン` `🍲鍋1つ`）に該当する記録数。
3. **🥢 プラス1品のゆとり**：主菜＋汁物・副菜まで気を配れた日を拾う。**データ**：`evaluations` の日付に対応する `state.mealSlots[date]?.side`（`Lifestyle.QUICK_SIDES`）がある回数。
4. **⏳ 最高に恋しかった一皿**：「◯日ぶりに作った『〇〇』」という物語を作る。**データ**：同じ親料理（`Lifestyle.sameDish`）の前回調理日からの日数差（14日以上）が最大の料理。
5. **🛒 買い足し少なめで乗り切った夜**：冷蔵庫整理の達成感を見せる。**データ**：材料のうち常備品・調味料（`Lifestyle.keeps(i)` または `pantry === "have"`）を除いた買う食材が3品以下だった回数。
6. **🍋 気分のゆらぎ**：カロリーではなく「どんな気分の夜が多かったか」を振り返る。**データ**：`Lifestyle.tags(r)` の `light`・`rich`・`spicy` の集計（`planBalance` の `moods`）。

## 5. SNS 画像の設計

### 画面の構成（上から順に・9:16 ストーリーズ基準 1080×1920）
1. **ヘッダー（12%）**：期間ラベル（`2026年のわたしの食卓` 等）＋ レシート風の日付帯。
2. **主役の称号＆よはく（18%）**：「🧭 冒険家タイプ」「🏠 定番職人タイプ」などの丸い札と、横からのぞく「よはく」（1匹だけ）。
3. **ベスト3の料理タイル（38%）**：1位を大きく、2位・3位を横に並べる（料理が1〜2品の時は自動的に1枚・2枚レイアウトに変形し、空枠を出さない）。
4. **3つの数字とバランス帯（20%）**：等幅の大きな数字3つ（`🍳 ◯回作った` ｜ `🍽 ◯種類の料理` ｜ `🥬 ◯種の野菜`）＋ 帯グラフ1本（`🥩肉・🐟魚・🥚卵豆腐`）＋ `🎬 よく作った：〇〇さん`（動画レシピがある時のみ・ON/OFF可）。
5. **フッター（12%）**：リピごちアイコン＋`リピごち｜「今日なに食べる？」を過去の食卓から`＋専用QRコード。

### 投稿したくなる仕掛けとプライバシー配慮
- **偏愛と二つ名で個性が出る**：「偏愛ベスト3」と「ユニークなタイプ名」が中央にあることで、「うちは今月餃子ばっかり！」と会話が生まれてシェアしたくなる。
- **プレビューでの1タップ切り替え**：① **📷 写真（既定） ⇄ 🎨 イラスト**（自宅の食器を隠したい時に公式イラスト `cardArtOf` に統一） ② **料理名を出す ⇄ 隠す** ③ **家族の名前は「常に出さない（固定）」**（「ふたりとも『また食べたい』」「わが家の定番」に固定し、本名流出事故をゼロにする）。

## 6. 流入の設計（画像を見た人 → アプリを使い始めるまで）

1. **入口URL**：シェア文と画像のQRを `https://165cm.github.io/matagochi/lp/?from=review`（公開レシピが1位なら `&dish=starter-51` 等を付与）にする。
2. **LPの歓迎バナー**：`?from=review` の時はLP最上部に「🍳 シェアされた『わたしの食卓レビュー』からようこそ！ 今週の夜ごはんからふりかえってみませんか（2026年内ぜんぶ無料）」を表示。
3. **初日からシェアできる体験へ直結**：LPからアプリを開くと初回設定（写真12枚で好みを選ぶ → 最初の献立が完成 → ごはんタイプ診断）へ進み、**初日でも自分の「ごはんタイプ」画像をシェアできる**ようにする。`&dish=...` があれば「シェアされていた『〇〇』を最初の献立に入れて始める」を選べるようにする。
4. **匿名集計**：シェア時に `trackDaily("table_review_share")`、流入時に匿名集計へ `from_review` を1カウント足すだけ（個人や料理名は送らない）。

## 7. 「5. 決まっていないこと」への答え

1. **期間の切り替えの場所**：「月（‹ 11月 ›）」と「4週」が並ぶと迷うため、**4週は既存の「月別」に統合**し、上部に `1週 ｜ 月別 ｜ 3か月 ｜ ここまでの歩み ｜ 2026年` のチップを置く（「月別」の時だけ ‹ 11月 › を出す）。
2. **項目の絞り込み**：1画面に全部は出さず、**「主役1つ＋数字3つ＋帯1本＋次への一言」の4ブロック以内**に絞り、期間ごとに主役を入れ替える。
3. **栄養の見せ方**：`estimateRecipeNutrition` のグラム・カロリーは「不明」が多発するため使わず、`BALANCE_VEG` による**「🥬 使った野菜の種類数」と「🥩🐟🥚 主菜のバランス帯」**に絞る（適量レシピでも100%正確に数えられる）。
4. **チャレンジ精神の測り方**：はじめての料理・技・作り手以外に、**「14日以上ぶりの再登場」「普段と違う味の系統（洋・中・ピリ辛）」「図鑑の新しい章の開拓」**を拾う。
5. **タイプ（称号）の是非**：**入れるべき**。ただしレベルや上下関係は作らず、「🧭 冒険家」「🏠 定番職人」「⚡ 15分名人」「🥬 野菜たっぷり」「🐟 魚じょうず」など、どれも嬉しい横並びの二つ名にする。
6. **思わず投稿したくなる決め手**：がんばり自慢に見えず「うちのリアルな偏愛（ベスト3＋二つ名）」で会話が生まれること。そして1タップで公式イラストカードに変えられること。
7. **記録が少ない人への配慮**：「半年」は「🌱 ここまでの歩み（累計5食以上で解放）」、「2026年」は「3食以上で年間トップ3カードが作れる」ように条件を緩め、1〜2品の時は1〜2枚レイアウトに自動変形して空枠を出さない。
8. **家族での扱い**：作った回数やベスト3は**「わが家（世帯合算）」**とし、閲覧者（`isViewer()`）も同じレビューを見てシェアできるようにする。家族の個人名は画像に一切出さない。
9. **流入と特典（案）**：年内無料のため金銭特典より体験特典とし、「シェアされた家庭のお気に入り料理を、自分の最初の献立に1タップで入れて始められる」仕組みにする。
10. **年末（2026年12月）の最小構成**：「1週（既存レシート）｜ 月別（既存）｜ 🏅2026年まとめ」の3期間＋9:16画像生成（写真／イラスト切替つき）に絞る。

## 8. 最小で出すなら（年末に間に合わせる版）

- **入れるもの（12月中旬公開のMVP）**：
  - 期間切り替え（3つ）：「🧾 今週」「📅 月別（‹ 11月 ›）」「🏅 2026年（記録3回以上で解放）」
  - 確実に計算できる5項目：①作った回数・料理の種類数 ②偏愛ベスト3（1〜2品なら可変レイアウト） ③リピ vs はじめての数 ④主菜バランス帯＋使った野菜の種類数（`BALANCE_VEG`） ⑤わたしの食卓タイプ（6種）
  - SNS画像（9:16・1080×1920）：写真／公式イラストの1タップ切替（YouTubeサムネイルは除外してCORS回避）、料理名ON/OFF、プレビュー時 `Blob` 先行生成による iOS Safari 完全対応の共有・保存
- **後回しにするもの（年明け以降）**：3か月・半年タブ、🌈 5色の彩りパレット、1:1正方形サイズ、作り手ランキング＆ハッシュタグ自動生成、LP側の `?from=review` 専用バナー

## 9. 気になるリスク（続ける気持ちを下げてしまうケースと対策）

1. **「先月より減った」「空白だらけ」で落ち込むリスク**：「先月比 −◯回」や「達成率 ◯%」は一切出さない。記録が少ない時はカレンダーより先に「忙しくてもこの2品を作りました！」「通算で図鑑が◯枚に」と積み上げを主役にする。
2. **「栄養・バランス」で説教されたと感じるリスク**：赤や黄色の警告色は使わない。肉が続いた時も「🥩 お肉で元気をチャージした1か月！ 来週は🐟お魚を1日入れてみる？」と肯定＋次の1タップ提案に変換する。
3. **「作った！」だけで未評価の人が開くと0だらけになるリスク**：評価（また食べたい）が0件の時は「また食べたい 0品」を隠し、調理回数だけでベスト3を作った上で「⭐ 前回の料理に『また食べたい』をつけると好みの傾向も見えてきます」と優しく案内する。
