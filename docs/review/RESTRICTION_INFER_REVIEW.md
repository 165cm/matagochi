# レビュー資料（Codex 向け）：食べられないものの判定に、材料名からの推測も使う

## 1. 対象
- ブランチ：`claude/restriction-infer`（main `51142f9` から）。PR 4a（品ぞろえの棚卸し）の途中で見つけた安全に関わる不具合なので、別の小さな PR にした

## 2. 問題・変更後
**問題**：`Lifestyle.fit` は、食べられないもの（`restrictions`）を、材料名・`planning.contains`・材料ごとの `allergens`／`label_check` だけで照らしていた。材料名の文字列の一致なので、印がない料理では「豚こま」が「肉なし」を、「鮭」「ぶり」が「魚なし」を、「しょうゆ」が「小麦なし」を通っていた。材料名からの推測（`suggestPlanning` の `contains`）は、確認待ちの料理（`reviewable`）では使っていたのに、`fit` では使っていなかった
- 影響：原材料を確かめた（`ingredientsVerified`）けれど `contains` が足りない料理（利用者が保存・編集したレシピなど）。最初から入っているおすすめ38品は印がそろっているので、判定は変わらない（38品の「卵／乳／小麦／えびかに／魚／肉なし」で残る品数は前後で同じことを確認）

**変更後**（`lifestyle.js`）
- `fit`：食べられないものは、上に加えて `suggestPlanning(recipe).contains` でも外す。**苦手（`dislikes`）は今までどおり**（材料名と印だけ。だしのような推測で外しすぎない）
- 推測の表を少し広げた：肉に ささみ・手羽・牛（牛乳は除く）・合いびき・ウインナー。魚に サーモン・たら・ぶり・まぐろ・あじ・いわし・さんま・かじき（以前の「牛ひき」は「牛」に含まれる）
- 版：`APP_VERSION` `20261001-allergy`・`CACHE_NAME` `ripigochi-v137`（PR 4a〔#114〕の v136 と別の番号。後から公開する方を、その時に1つ上げる）

## 3. テスト
- `node --test test/*.test.cjs`：225件 成功（新しく `test/restriction-infer.test.cjs` 2件。**2件とも修正前のコードでは失敗することを確認**）
  1. 印のない料理で、豚こま・牛こま・ささみ → 肉なしで外す／鮭・ぶり → 魚なしで外す／しょうゆ → 小麦なしで外す／牛乳は肉ではない／ひきわり納豆は肉ではない／条件がなければ通る
  2. 苦手は推測で広げない（「魚が苦手」でみそ汁は出る。「魚が食べられない」ならみそ汁は外す〔だし〕）／名前が一致する苦手は外す
- `npm test --prefix api`：142件 成功（変更なし）

## 6. 影響
- 食べられないものがある人の献立の候補が、印のない料理の分だけ減ることがある（安全側）。候補が足りなければ、今までどおり条件をゆるめず、同じ料理が出る／「条件に合う候補がありません」
- 保存・同期・API：変更なし

## 7. コードだけでは完了できないこと
- 推測の表（とくに「みそ・めんつゆ・ポン酢・キムチ → 魚」）が強すぎないか。食べられないものは安全側に倒している
