# 献立決めUX 第3回の相談：4つのAIの比較（2026-11-07）

資料：`docs/review/MENU_DECISION_REVIEW3_AGENDA.md`／Claude の回答：`docs/review/MENU_DECISION_REVIEW3_CLAUDE.md`
Codex・Gemini・Grok の回答はユーザーがチャットに貼ったもの（要点を下にまとめた）。

## 1. 4つとも同じ意見

1. **消去法は主役として良い**。「これは違う」は選ぶより楽。**消した1枠だけ入れ替わり、残りの3枚が比べる相手として残る**のがいちばんの改善
2. 「1品では少し、重なるほど強く」「除かずに後ろへ回す」で、第2回の心配（決めつけ・全滅）に答えられている
3. **✕ は写真の上から外す**（サムネイルの文字にかぶる・写真を押して選ぶ時に押し間違える）。写真の下の「⏱時間」の行の右はしへ（Claude・Codex・Gemini。Grok も「写真の外」）
4. 消した特徴は **その場だけ** が基本。ずっと残す好みには自動では入れない
5. 「少なめに」は手応えになる。ただし文字は減らす

## 3. ほかのAIからの良い指摘（取り入れたい）

- **画面が動く**：「少なめに」が出た時・✓ をつけた時に、写真の位置がずれる。状態の行と下の操作の場所の高さを固定し、料理名も2行分を取っておく（Codex）
- **✕ が多い**：閉じる ✕・料理を消す ✕・少なめを外す ✕ が同じ形（Gemini・Codex）→ 料理を消すのは「パス」など言葉つき、少なめを外すのは「解除」
- **消した料理と同じ料理名**は、その場では別の作り方も出さない（Claude・Codex）
- **気分の札で「🐟 魚」を押していたら、魚の「少なめ」は止める**（本人の指定を推測より優先。Codex）
- **元の献立の料理**も、少しだけ「消した」扱いにする（変更を開いた＝今夜の気分ではない。Gemini）
- **「↩ 戻す」で、消した料理と一緒に、その操作でついた「少なめ」も戻す**（今の作りはそうなっている）
- 成功の測り方：消去回数ごとの決定率は「その段階まで来た人」を分母に（Codex）／**入れ替わって新しく出た料理が選ばれた割合**（Gemini）／「少なめ」の解除率が1割以下（Gemini）／特徴の減点ありとなしを比べる（Codex）

## 4. Claude が考えを改めたこと

- 「4皿とも消す」は重みを半分ではなく、**特徴を学ばない「🔄 別の4皿」**にする（Codex・Gemini）
- 「消したお皿の列」より、**気分の札がそのまま「🙅 魚 少なめ」に変わる形（Gemini）**のほうが行が増えず、画面も動かない。1品目は「↩ 戻す」だけ
- 肉の二重の足し算をやめる（Codex・Gemini の指摘どおり、今は「鶏」を消すと豚・牛まで強く下がる）

## 5. まとめた案（たたき台）

1. ✕ を写真の下の行の右はしへ。言葉つきの「パス」（押せる大きさ44px）。写真の上は ✓ だけ
2. 状態の行は高さを固定。1品目は「↩ 戻す」だけ。2品以上で共通した特徴は、気分の札の列に「🙅 魚 少なめ（解除）」として出す（最大2つ）
3. 重み：同じ主役（鶏・豚・魚 など）1.5／大きな種類だけ同じ 0.5（魚は1.5）・主役と二重に足さない／食べ方の形 2／こってり・ピリ辛・さっぱり・汁もの 2（合計に上限）／和洋中 0.5／時間は使わない。同じ特徴の強さは 1回=1・2回=1.5・3回以上=2 で頭打ち
4. 消した料理たちが同時に2つ以上の特徴を共有している時（魚の丼だけを2品）は、その特徴たちは強くしない・「少なめ」にも出さない
5. 消した料理と同じ料理名は、その場では出さない。元の献立の料理は0.5品分「消した」扱い。気分の札で選んだ特徴は「少なめ」にしない
6. 「🙅 4皿とも消す」→「🔄 別の4皿」（特徴は学ばない）
7. 下の操作の場所は高さを固定し、✓ をつけたら「✓『◯◯』にする」に入れ替わる
