# 毎日の食生活UX（2026-09-23）

対象は1人・2人暮らしの夜ごはん、単品料理。無料機能のまま、最初の設定→数日分の献立→買い物→調理→振り返りをつなぐ。月980円の価値検証を目指すが、この変更で課金・栄養モード・価格比較は導入しない。

## 画面と初回設定

下部は「今日／献立／買い物／レシピ／ふりかえり」。設定は右上。今日には状態ごとに次の操作を表示する。料理写真がないときは「料理のイメージ」と明示した器のイラストを使う。架空の栄養値・節約額・写真は表示しない。

初回の16画面は人数、自炊日と提案日数、食べられないもの、苦手食材、好きな味、平日休日の時間、難易度と避けたい作業、器具、常備品5カテゴリー、買い物頻度と節約希望、使い切り希望、設定一覧。未回答は保留できる。器具・常備品は `have / none / unknown`。器具画面は「基本の道具／あると便利／こだわりの道具」の3グループとワンタップ切り替え。初回表示時、未回答の基本器具9点を `have`、その他を `none` で初期設定する。これは実測所持率ではなく入力を短くするための製品上の初期値で、画面に明記する。既存の回答（未確認も含む）は上書きしない。常備品の初期値は従来どおり未確認。常備品も絵文字付きカードのワンタップ操作に統一し、未確認→ある→ないを区別して保持する。選択カードは通常3列、狭い画面では2列。曜日は1列に収め、説明と余白を短くする。絵文字は装飾として扱い、文字ラベル・選択状態も併記する。追加の器具や調味料も登録できる。

設定済みユーザーは一覧から項目へ戻れる。既存ユーザーには設定を案内するが、通常画面をロックしない。好みの設定が完了すると候補へ適用される。使い切り希望は設定完了日から7日間だけ有効で、実在庫として恒久管理しない。

## 提案と確定

- `lifestyle.js` はDOMに依存しないプロフィール・候補・買い物・マージのルールと、オリジナルの初期料理12品を持つ。`daily-ui.js` が画面と既存アプリを接続する。
- 未確認の調理条件は自動献立に入れず、入れ替え一覧から確認して確定する。既知の食材・器具・作業・時間の制約は緩めない。
- 好きな味、期限内の使い切り希望、常備品、リピート希望で並べ、節約希望なら同じ食材を使う料理を加点する。十分な保存料理があるときは初期候補が続かないようにする。
- 原材料が未確認、または対応する食材区分以外の制限がある場合は自動候補にしない。これはアレルギー安全性の保証ではない。市販品の原材料表示の確認を案内する。
- 食材区分の対応は卵・乳・小麦・えび・かに・そば・落花生・くるみ・大豆・魚・肉。食材名・区分で照合する。完全な食材辞書や交差接触の判定は行わない。
- 保存レシピの編集では任意の調理時間・器具・作業・味・難易度・確認済み食材区分を設定できる。材料名や手順を編集すると原材料の確認フラグを外す。
- `mealSlots[date]` に人数、料理の複製、状態、更新時刻を保存。表示や再起動で再抽選しない。個人設定と合わなくなった確定料理には注意を表示し、勝手に変更しない。
- レシピ編集や表示人数変更は確定内容に波及しない。「今のレシピ・人数を反映」で明示適用する。候補の入れ替えは最大3案とレシピ画面への導線を表示する。
- 初期料理は静的なオリジナルデータ。保存・編集・調理記録時には自分用コピーを作成し、共通URLレシピDBへ書き込まない。実食による味・所要時間検証は別途必要。

## 買い物・記録・同期

買い物は確定かつ未調理の献立のみ。頻度が毎日なら今日、週なら7日、数日・未指定なら提案日数が対象。レシピごとの元人数と確定人数で換算する。名前を軽く正規化し同じ単位は合算、換算不能な単位は併記する。

所有確認済み常備品は「家にある」。明示的に「買う」へ戻せる。購入・所有チェックには必要量の署名を持たせ、追加・増量などで再確認する。予定の削除だけで必要な材料が減る場合は既存チェックを保つ。変更時は追加・不要・変更件数を表示する。数量不明・所有品の残量を推定しない。旧 `shopping.checked` はバックアップ内に保持し、確定前の候補と数量が異なる新リストへは自動適用しない。

「作った」は日付ごとに重複しない記録を作る。「また食べたい」を押すまでは好みを未設定に保つ。写真・メモ・好みはふりかえりの各記録から編集する。

合言葉同期の既存APIに、世帯の所有品・確定献立・買い物状態を追加。日付／項目ごとの更新時刻でマージし、削除は `removed` / `deleted` として保持する。同時刻は安定した比較で収束させる。個人設定・食材制限・初回設定下書き・操作計測は送らない。JSONバックアップは全状態を含む。全端末を新版へ更新して使うこと（旧クライアントの全状態アップロードは新しいフィールドを扱わない）。

## 検証とテスト手順

```sh
node --check lifestyle.js
node --check daily-ui.js
node --check app.js
node --test test/*.test.cjs
npm test --prefix api
python3 -m http.server 8124 --bind 127.0.0.1
```

PlaywrightとChromeを利用できる環境で別ターミナルから `node scripts/check-daily.cjs`。外部にインストールしたPlaywrightは `PLAYWRIGHT_MODULE` でモジュールパスを指定できる。画面テストは新規の一時ブラウザを使い、実データ・有料AI呼び出しを使用しない。

1. 新規ブラウザで初回設定。途中で閉じて再開し、回答と進捗が残ることを確認。
2. 1人／2人、調理時間、持っていない器具、常備調味料を設定。提案理由と候補を確認。
3. 3日分を確定。買い物で所有品の分離、購入チェック、手動追加を確認。
4. 献立を変更し、追加・不要・数量変更の表示を確認。再起動して確定内容が同じか確認。
5. 今日から作り方を開き「作った」。ふりかえりから写真・メモを追加。好みは任意で記録。
6. 設定の一覧から条件を変更。確定した料理は保持され、不適合なら注意が出ることを確認。
7. 保存レシピを編集。確定献立が自動変更されず、明示操作で反映できることを確認。
8. 320〜430px、文字拡大、オフライン再起動、バックアップ復元、別端末マージを確認。

端末内 `experienceEvents` に回答内容を含めず操作種別・時刻・ステップ番号などを最大500件記録する。初回開始・章通過・完了・献立確定・入れ替え・買い物完了・調理を対象とし、外部アナリティクスは導入しない。実ユーザー5人の操作テスト、開始者を分母にした離脱・継続・将来の課金率の検証は公開後に行う。


## 2026-09-24 導線改善

- 保存画面に時間（10/20/30分＋自由入力）、器具、作りやすさ、作業、食材区分の確認を常時表示。
- AI抽出済みの材料・手順と手動入力に共通のローカルルールで、器具・食材区分の候補を作る。追加のAIリクエストはしない。時間と作りやすさは推定せず利用者が選択する。食材区分には市販調味料の確認候補も含むが、候補の完全性を保証せず原材料表示との照合を求める。
- 通常保存は調理条件・材料表示の確認を必須とする。不明なら「未確認で保存」を選べる。画像の内容確認はこの経路でも省略不可。
- 未確認の保存レシピは入れ替え一覧に「確認が必要」と表示し、編集で条件を確定してから選択する。確認後は入れ替え画面に戻る。判明している食材制限やリピなし、時間超過を緩めない。
- 買い物はチェック1回で購入済み。「家にある」は各行のメニュー。売り場別に表示し、米を所有していると回答した場合のみ炊飯済みごはんも家にあるとして扱う。炊飯後の重量を生米の重量へ換算しない。
- 今日と過去3日分の確定献立を記録可能。ホーム上の「作った？」で過去分を記録する。日付は調理日のまま保持し、同日献立の重複記録を防ぐ。
- 記録直後の1回だけ6段階の頻度を表示。回答は利用者本人の記録。「あとで」は自動で再表示せず、ふりかえりの編集で変更できる。

検証: `node --test test/*.test.cjs`。
実ブラウザ: `node test/ui-server.mjs` を起動し `node scripts/check-ux.cjs`（Playwright＋Chrome）。

再生リストの一括保存も未確認の下書きとして扱う。自動献立には入れず、献立の入れ替え候補から確認する。APIの対応状況をhealthで確認できるまで新しい入口を表示しない。
